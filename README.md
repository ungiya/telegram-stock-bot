# 관심 종목 뉴스 → Telegram (검색어 수에 따른 자동 주기)

GitHub는 코드와 자동 배포 소스, Cloudflare Workers는 매분 실행, D1은 기사 중복 기록과 운영 설정을 담당합니다. 현재 기본 목록은 달바글로벌을 포함한 26개입니다. 뉴스 필터는 기존 Termux 코드에서 옮겼습니다. 리포트 수집도 클라우드에서 실행합니다. 다중 구독자 관리는 아직 이전하지 않았습니다.

## 텔레그램에서 관리

기존 봇의 **개인 대화창**에서 다음 명령을 보냅니다.

| 명령 | 기능 |
|---|---|
| `/list` 또는 `list` | 클라우드에서 실제 검색하는 종목 목록 |
| `/add 회사명` | 종목 추가; 첫 검색은 과거 기사 기록만 저장 |
| `/remove 회사명` | 종목 검색 제외 및 해당 종목의 대기 기사 발송 취소 |
| `/status` | 검색 주기, 목록 수, 정지 여부, 최근 검색 상태 |
| `/pause` | 검색은 계속하고 뉴스·리포트 전송 정지; 정지 중 발견된 기사는 다시 보내지 않음 |
| `/resume` | 뉴스 전송 재개 |
| `/start`, `/help` | 사용법 |

명령은 Cron 실행 시 확인하므로 통상 약 1분 뒤 응답합니다. 검색 지연·명령 대기열이 있으면 더 걸립니다. 최초 실행은 이전 Termux 명령을 재실행하지 않도록 수신 위치만 초기화합니다. 배포 후 첫 Cron이 지난 뒤 새 `/list`를 보내세요.

**Termux의 기존 봇은 중지해야 합니다.** 같은 토큰으로 두 곳에서 `getUpdates`를 호출하면 명령을 서로 가져가거나 충돌할 수 있습니다. 이미 Telegram webhook이 설정돼 있으면 자동으로 삭제하지 않고 명령 수집을 중단하며 로그를 남깁니다. 뉴스 검색은 계속 시도합니다.

### 관리자 확인

- 뉴스 대상이 개인 ID면 그 사용자만 개인 대화에서 명령을 사용할 수 있습니다.
- 뉴스 대상이 채널·그룹이면 해당 대상의 소유자 또는 관리자인지 `getChatMember`로 확인합니다. 봇에게 대상의 관리자 권한이 필요합니다.
- 채널 게시물·그룹 메시지·익명 관리자의 메시지로는 목록을 수정할 수 없습니다. 반드시 봇의 개인 대화창에서 관리하세요.
- 인증 실패 시 목록과 설정을 공개하거나 수정하지 않습니다. 처음 명령을 보낸 사람에게 관리 권한을 주지 않습니다.

### 목록의 저장 위치

`src/watchlist.js`는 기본 종목과 검색 별칭입니다. Telegram 추가·삭제는 D1 `watchlist_overrides`에 저장되고 기본 목록과 합쳐 실제 검색에 사용됩니다. 삭제된 기본 종목은 다음 배포 후에도 삭제 상태를 유지합니다. 같은 종목을 `/add`로 다시 등록할 수 있습니다. 코드에 기본 종목을 추가하면 자동 반영되지만, D1에서 명시적으로 삭제한 종목은 `/add`가 필요합니다.

## 배포

현재 Cloudflare Workers Builds가 GitHub main을 소스로 사용합니다.

- 프로젝트명: `telegram-stock-news-alert`
- Build command: `npm test`
- Deploy command: `npm run deploy`
- `npm run deploy`는 D1 마이그레이션 후 Worker를 배포합니다.
- Cron: `* * * * *`
- D1 바인딩: `DB` / `telegram-stock-news-db`
- 마이그레이션: `0001_init.sql`(기사), `0002_commands.sql`(명령·설정), `0003_reports.sql`(리포트)

별도 GitHub Actions 워크플로도 저장소에 있지만, 현재 Workers Builds와 함께 활성화해 이중 배포하지 마세요. Actions를 별도로 사용하려면 Cloudflare 계정 ID와 배포 토큰을 GitHub Secrets에 등록해야 합니다.

Workers Production의 Secrets:

- `NAVER_CLIENT_ID`
- `NAVER_CLIENT_SECRET`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

기존 Naver API Hub 인증정보를 사용합니다. 일반 네이버 개발자센터 인증정보와 혼동하지 마세요. API 주소는 `https://naverapihub.apigw.ntruss.com/search/v1/news`입니다.

## 동작과 한계

제목에 종목명·별칭이 포함된 최신순 100건을 확인합니다. 광고·단순 시세·크래프톤 대회 제외 규칙을 적용하고 최근 24시간 기사를 발송합니다. D1에 원문 URL을 기록해 중복 발송을 막고 한 번에 최대 10건을 묶습니다. 첫 검색은 기존 기사 기준선만 기록합니다. 검색 색인과 예약 실행이 지연될 수 있으며 제목·요약만으로 거르는 필터에는 한계가 있습니다. Telegram 전송 직후 DB 저장이 실패하면 드물게 중복될 수 있습니다.

실행이 겹치면 D1 잠금으로 뒤 실행을 건너뜁니다. 중단된 실행의 잠금은 5분 후 만료됩니다. 명령 재시도 시 변경은 중복 추가되지 않지만, 응답 메시지가 중복되거나 앞선 변경을 확인하는 문구로 바뀔 수 있습니다. `/pause` 전에 이미 대기 중이던 기사는 재개 후 전송될 수 있습니다.

`GET /health`는 단순 상태 응답이며 실제 검색·전송 성공을 보증하지 않습니다. 로그의 `Checked … tickers`와 Telegram 수신으로 운영을 확인하세요.

## 비용

기본 26개 종목·30개 검색어는 매분 실행 시 하루 43,200회 API 호출입니다. 종목 추가 시 호출 수가 증가합니다. Naver API Hub 실제 무료 할당량·과금 설정과 Workers/D1 무료 한도 충족은 별도 확인이 필요합니다. 비용 0원이 보장된 상태는 아닙니다.

저장소는 공개입니다. 비밀키·토큰·운영 state.json을 코드나 커밋에 올리지 마세요. 비밀값은 Cloudflare Secrets에 보관합니다.


## 증권사 리포트

기존 `reports_feed.py`, `broker_collect.py`, `report_schedule.py`에서 옮겼습니다.

- 직접 수집: 삼성증권(35건), 하나증권, 미래에셋증권, 한국투자증권(3페이지), NH투자증권(AI Brief 제외), KB증권(최근 14일 목록)
- 네이버 통합 리포트: 최신 15페이지·최대 300건. 특정 4개 증권사로 한정하지 않으며 목록에서 제공하는 증권사 리포트가 대상입니다.
- 한국시간 매일 08:00·18:00·23:00부터 수집. UTC Cron은 `0-14 9,14,23 * * *`입니다.
- 한 번에 한 수집처를 처리하고 몇 분에 나눠 작업합니다. 각 시간대의 처음 15분 동안 수집·상세 조회·발송과 실패 재시도를 처리합니다. 뉴스 Cron과 별도로 실행해 뉴스 검색 요청 예산을 쓰지 않습니다.
- 관심 종목은 뉴스와 같은 D1 운영 목록입니다. `/add`와 `/remove`가 양쪽에 적용됩니다. 네이버 목록은 종목명 정확히 일치, 직접 수집 목록은 제목에 종목명·별칭이 있는지 확인합니다.
- 수집처별 첫 성공은 기존 리포트를 기록만 합니다. 그 이후 발견한 새 리포트부터 발송합니다. 이미 Termux에서 발송했던 기록은 이전하지 않아, 전환 후 첫 기준선을 이렇게 만듭니다.
- 같은 회사·증권사·날짜·정규화된 제목을 묶어 원문과 네이버 경유 중복 발송을 줄입니다. 제목이 다르면 중복을 완전히 막지는 못합니다.
- 네이버 상세의 종목 코드를 검증하고 신뢰하는 PDF 주소만 사용합니다. PDF가 없으면 공식 리포트 상세 주소를 보냅니다. 일부 증권사는 로그인·열람 권한이 필요할 수 있습니다.
- 실패한 수집처는 최소 2분 후 같은 시간대 안에서 재시도합니다. 다른 수집처와 뉴스는 계속합니다. HTTP 503 등 실패를 수집 성공으로 표시하지 않습니다. 수집처 화면/API가 바뀌거나 접속이 차단되면 수정이 필요합니다.
- `/status`에서 일정과 최근 수집 경로 수·발송/대기 수를 확인합니다. `리포트 수집 7/7 경로`는 6개 증권사와 네이버 목록을 의미하며 7개 증권사를 의미하지 않습니다.
- 외부 요청은 리포트 호출당 최대 40회, 발송은 최대 6건으로 제한합니다. 대량 대기 자료는 뒤 호출 또는 다음 시간대로 넘어갈 수 있습니다. 15분 창 밖에서는 리포트를 발송하지 않습니다.
- 실제 Cloudflare CPU 한도·원격 수집 성공 여부와 Telegram 리포트 수신은 배포 후 로그로 확인해야 합니다. 무료 운영을 목표로 하며 유료 플랜으로 전환하지 않습니다.

## DART 공시 알림

- OpenDART 공식 공시검색 API를 별도 매분 Cron(`0-59 * * * *`)으로 실행합니다. 뉴스·리포트 작업과 외부 요청 예산 및 잠금을 분리합니다.
- Production Secret `DART_API_KEY`에 본인 OpenDART 인증키를 등록하면 활성화됩니다. 키가 없으면 공시 작업만 건너뛰며 뉴스·리포트는 계속 작동합니다. 키를 소스, 로그, 채팅에 넣지 마세요.
- [인증키 신청](https://opendart.fss.or.kr/uss/umt/EgovMberInsertView.do) 후 Cloudflare 해당 Worker → Settings → Variables and Secrets → Add에서 이름 `DART_API_KEY`, 유형 Secret으로 등록·Deploy합니다.
- 기존 `/list`, `/add`, `/remove`의 운영 관심 종목을 그대로 사용합니다. 법인명·별칭이 정확히 일치하는 공시가 대상이며 종속회사 이름의 부분 일치는 허용하지 않습니다. 비상장기업도 DART에서 제공하는 공시에 한해 대상입니다.
- 공시 제목, 접수일, DART 원문 링크를 기사와 별개의 메시지로 보냅니다. 접수번호로 중복을 방지하며 새 접수번호를 가진 정정공시는 별도 발송합니다. 뉴스 유사도 및 언론사 차단 필터는 공시에 적용하지 않습니다.
- 첫 전체 목록 확인과 신규 종목 추가 직후에는 기존 공시를 기록만 하고 이후 발견한 새 공시부터 알립니다. 목록이 많으면 초기 확인에 여러 분이 걸릴 수 있습니다.
- 한국시간 오늘·어제 목록을 확인합니다. 최신 100건은 매분 먼저 확인하고 나머지 페이지는 저장한 위치에서 이어서 확인합니다. 호출당 API 최대 8페이지(페이지당 100건), 발송 최대 5건으로 제한합니다. 공시가 몰리거나 전송 대기가 많으면 알림이 더 늦어질 수 있고 2일 이상 장애는 자동 복구 범위를 벗어납니다. 공시 등록 즉시 또는 1분 이내 도착을 보장하지 않습니다.
- `/pause`·`/resume`가 공시 발송에도 적용됩니다. 일시정지 중 수집한 공시는 재개 후 발송될 수 있습니다. `/remove`는 해당 기업의 미발송 공시도 정리합니다.
- `/status`에서 인증키 대기, 최근 확인 및 오류 상태를 확인합니다. API 오류는 과거 공시 기준선 초기화 성공으로 취급하지 않으며 키를 포함한 요청 주소는 로그에 남기지 않습니다. Telegram 성공 후 DB 기록 전 장애가 발생하면 드물게 중복될 수 있습니다.
- `npm run deploy`가 D1 마이그레이션(`0006_dart.sql` 포함)을 먼저 적용합니다. 공시 수집 코드와 테스트 통과만으로 실제 배포·API 키 유효성·Telegram 수신이 확인되는 것은 아닙니다.

## 뉴스 자동 검색 주기

뉴스는 관심 종목의 별칭까지 포함한 검색어 수를 기준으로 2·3·5·10·15·30·60분 중 주기를 자동 선택합니다. 31일 기준 월 620,000회 이하로 예상 호출량을 유지해 공개 월 한도 775,000회의 20%를 남깁니다. 현재 기본 26종목/검색어 30개는 3분, 월 최대 약 446,400회입니다. add/remove 후 다음 실행부터 다시 계산하며 /status에서 현재 주기를 확인할 수 있습니다. 공시와 명령 확인은 매분, 리포트 일정은 그대로입니다.

검색 시도 시각은 D1에 먼저 기록하므로 실패나 재배포도 주기를 초기화하지 않습니다. 이 계산은 네이버의 실제 잔여량을 조회하는 기능이 아닙니다. 기존에 사용한 양, 같은 키의 다른 프로그램, 별도 일일/월별 한도에 따라 429가 계속될 수 있습니다. 이미 소진한 한도는 이 변경으로 즉시 복구되지 않습니다.
